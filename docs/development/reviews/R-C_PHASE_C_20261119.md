## Findings

### Registry re-registration (C1): correct

`_check_free` now treats a repeat (same `fn` object, specs equal slot by slot, same
`unbounded`/`indenter`/`check`) as a no-op and still raises on a different registration
under a taken name. `register_distribution` compares the frozen `Distribution`;
`register_class_kind` compares class and `vars()`. Function identity is the right test: a
plugin's `register()` imports the same module object each time. A spec default that is
NaN would compare unequal and raise, which errs on the safe side. The registries hold
the same objects as before for a first registration, so no draw changes.

### Filter state: the base class contradicted the engine (fixed here)

`SimulationEngine` calls a filter's `forward()` once per stimulus and never calls
`reset_state()` (its comment: "resets state on each call via BaseFilter contract"). The
built-in SA and RA filters satisfy that through `reset_states=True` by default. But
`BaseFilter`'s docstring told authors to implement `reset_state()` and that it "must be
called between independent sequences", and `add_filter.md` said it clears state "between
runs". C6's second live run found exactly this: the scaffolded filter carried state across
calls and failed `core.run.determinism` and mirror symmetry. C6 fixed the scaffold. This
review fixes the contract text: `BaseFilter`'s docstring and the `add_filter.md` table now
say `forward()` starts from rest on every call.

`check_component("filter", ...)` still does not catch a stateful filter (it runs one
forward pass). A second pass compared with the first would; the noise filters in
`filters/noise.py` would need to be exempted or seeded. Recorded as `Opens:`.

### Skill reference files (C2c): one gap

`install` removes a dropped skill's generated `reference.md` along with its `SKILL.md`.
A skill that stays but loses its `reference.md` in a later release keeps the stale
generated file beside it. No skill does that today. Recorded as `Opens:`.

### Scaffold (C2b, C6): correct

The `innervation` kind has its own plugin test template (the class needs coordinates to
build). The grid placeholder draws from a seeded generator, so
`from_config(to_dict())` reproduces its points, and its test checks that. The filter
placeholder starts from rest on every call.

### Contract checks (C4, C2d): correct

Every kind in `_CHECKS` now runs the full `to_dict()` completeness check, processing
layers against their `{method, params}` shape; `AdaptiveSolver` keeps `method`, `rtol`
and `atol`. The docstring's rule that a built-in that cannot pass becomes an open item,
never a weaker check, is the right one.

### Reference plugins (C5): correct

The ring shape says its formula is a teaching example and its ranges are placeholders,
which keeps to the rule that agents and examples do not invent domain facts. The leaky
neuron accepts `noise_std` as membrane noise, matching the engine (C-130). The plugins'
own `tests/` folders are outside `testpaths`; `tests/integration/test_reference_plugins.py`
covers them by running all three in one data set.

That test left the three plugins registered in the process-wide registries, so the full
suite failed later at `tests/unit/test_describe.py::test_committed_schema_is_current[config]`
(the schema then listed `leaky_threshold`). Targeted runs never showed it. Fixed here: the
fixture restores `NEURON_REGISTRY`, `FILTER_REGISTRY` and `SHAPE_KINDS` afterwards.
