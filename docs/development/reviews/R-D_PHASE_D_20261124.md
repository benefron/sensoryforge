## Findings

### The quick starts and the README: correct, with one overclaim (fixed here)

Every command ran from the wheel and printed what the page shows: the extend quick start
(scaffold `Smoother`, `pytest` 1 passed, listed under Filters, `validate`, `run`, 600
spikes, `config.json` records `filter_method: smoother`); the command-line quick start
(the preset run; the merged `gaussian.yml`; `load_bundle` gives `[200, 900]` and
`[200, 80, 80]`, as shown); the world quick start (`world validate` prints the id
`w-b820f0863eba` shown on the page; `evaluate run` 40 draws, 32 s wall, all six stages
ok, 13 checks passed); `examples list|copy`; and the README's scaffold folder name
`sensoryforge-my-neuron`. The README's three ledger ids exist.

The overclaim: the README, the quick-start table and the extend page said the same steps
take a solver or a grid arrangement into a config. They do not: no config key builds a
plugin solver (F-74f5c58) and `GridConfig.arrangement` knows only the built-in names
(F-5f4e887). Both limits are already stated on `extending/add_solver.md` and
`extending/add_grid_arrangement.md`. **Fixed here:** the three places now name the kinds
that reach a config (neuron, filter, stimulus, receptive-field builder) and point the
other two at their pages.

The world quick start's "look at it" step ran the comparison stage with the same folder
twice and no word on why, and that step rewrites `compare.json`. **Fixed here:** one
sentence says which argument is which and that it rewrites the file.

### `first_simulation.md` is broken (required change 1)

The quick-start page sends Python users to [First Simulation]. Its script fails in two
ways:

1. `sa_neurons: 100`, `ra_neurons: 196` are per-row counts on this legacy path, so it
   asks for 196 × 196 RA neurons on 6 400 receptors and raises `ValueError` (dense weight
   tensor over the cap). This is DR-01, fixed on the old quick start in D1b-A but not
   here.
2. With the counts corrected (10, 14, 5), the run completes, but the spikes come back
   batch-first, `[batch, time, neurons]`. The page treats them as `[time, neurons]`:
   "Duration" prints 0 ms and the first raster plot fails
   (`sa_spikes.nonzero(as_tuple=True)` returns three tensors, not two).

It also teaches the legacy `GeneralizedTactileEncodingPipeline.forward(stimulus_type=...)`
API, which D3 removed from the quick start. The snippet test did not catch this, because
it parses Python blocks and does not run them. The site map already merges this page,
`getting_started/quickstart.md` and `tutorials/quickstart_tutorial.md` into one "Your
first simulation" tutorial. That is where this is fixed: rewrite it on the canonical path
(a canonical config through `SimulationEngine`, or `load_bundle` after a run) and run
its complete script in a test with a short duration.

### The site restructure has not started (required change 2)

Ben's answers of 2026-11-02 (f787d90), and D-22e8a63, which put the work in phase D
after phase C: four kinds of page (tutorials, how-to, reference, concepts), one file

  applied).

  every docs path named in code, the README and the packaged report contract exists (the
  audit's precondition for any move).
- Public pages still carry 179 ledger ids, 103 Phase/Wave labels and 15 `docs_root`
  mentions, on 36 pages. Most of them are on `developer_guide/architecture_notes.md`
  (84), `developer_guide/roadmap_v1.md` (46), `user_guide/configuration_schema.md` (18),
  `concepts/sensor_arrays.md` (14), and `user_guide/units_and_gains.md`,
  `concepts/units_and_shapes.md` and `concepts/pressure_simulation_use_case.md` (10
  each). `agents/decisions.md` (29) is Q2's one exception. The 19 `CLAUDE.md` mentions are

- `developer_guide/roadmap_v1.md` and `EQUATION_DSL_IMPLEMENTATION.md` are still in the

The changelog says "a reworked docs site", which is true only once this is done. The
redirects matter more now than when the audit was written: the README and the packaged
report contract link to site URLs (`/getting_started/quickstart/`,
`/developer_guide/audit_reader/`, and so on), so a move without redirects breaks an
installed release's links. The link checker checks the site's own addresses against the
local build, so it will catch a missing redirect if it runs on the moved site.

### `docs/development/agent_runs/` was published (fixed here)

`exclude_docs` left out `development/agent_runs/`, so the C6 run's `results.json`, its
JSONL transcript (which holds a local home-folder path) and a scores page were built into
the site. The files are already in the public repository. **Fixed here:** the folder is
added to `exclude_docs`, and the built site no longer has a `development/` folder.

### The changelog: three inaccuracies (fixed here)

- "Every snippet in the docs is run by `test_docs_snippets.py`": the test parses
  commands and Python blocks and checks imports; it does not run them (that is how
  `first_simulation.md` got through). Now says what it checks.
- "World field names are unit-free": they are aliases normalised to the `_mm` names at
  load (8cf4e60), and old worlds are unchanged. Now says so.
- `check_evaluation_component` was listed under Fixed; it is an addition, and has moved
  to Added.

### The code: correct

`examples list|copy` refuses an unknown name and an existing file without `--force`, and
reads through `importlib.resources`, so it works from a wheel (checked). The packaged
report contract equals the docs page with its relative links pointed at the site
(a test keeps the two equal, and another checks that every link points at the site).
`check_docs_links.py` needs only the standard library. No bare `except`, no `assert` on
input.

- `sensoryforge list-presets` prints internal labels in two preset descriptions (`D-019`

  is not affected.
- D3's timing by a new user and D6's version bump and tag are Ben's. Neither blocks the

- Main's CI non-GUI jobs are already red (F-16f7ce4, golden tolerance; F-439d607,
