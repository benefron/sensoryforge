# Skills Reference

This page is for anyone who wants to see what each SensoryForge skill does before an
agent runs it. It is generated from the skill files that ship in the package
(`sensoryforge/agents/skills/<name>/SKILL.md`), so it says what the installed skills
say. For each skill: when an agent picks it, the steps it follows, and its worked
example.

The worked examples are not illustrations. The test suite writes each example's files
into an empty folder and runs its commands, checking what each prints (`# prints:`) and
its exit code (`# exit:`), so an example that drifts from the code fails before a
release. To run one yourself, copy its files into a new folder and run its commands
there.

You do not name a skill to use it: say what you want and the agent picks the skill
whose purpose matches what you mean. The short table is in
[Skills for a Coding Agent](../user_guide/agent_skills.md); how the skills work with
you is set in the [setup](../user_guide/agent_setup.md).

## SensoryForge setup

`sensoryforge-setup`

**When an agent uses it.** Set up how SensoryForge's agent skills work with this user. Use when someone first works with SensoryForge through an agent, or asks to change how the agent works with them (their own tools, planning, subagents, parallel work, session or token limits, reviews, pauses between steps, hooks), in whatever words they put it.

Ask, never assume. Every question has a self-contained default; when the user does not
answer, says "defaults" or wants to skip, the default stands.

**Steps.** Read what is saved; Their own tools; How they like to work; Hooks (only where they work); Save and show.

### Worked example

The user wants subagents only for reading, and a session budget of 150000 tokens; they
accept the other defaults. The skill saves the answers without questions and reads the
brief back:

```bash
sensoryforge agents setup --no-input --path .sensoryforge/agents.yml --integrate no \
    --subagents read-only --session-tokens 150000
# prints: Saved
sensoryforge agents brief --path .sensoryforge/agents.yml
# prints: only for independent read-only work
# prints: about 150000 tokens
```

## Design and plan

`sensoryforge-design-and-plan`

**When an agent uses it.** Turn a SensoryForge goal into a written plan of steps and choices before anything runs. Use when someone says what they want to study, build, test or compare with SensoryForge (a set of stimuli, a data set, a sensor, an experiment, a new component) and has not yet said exactly what to run, in whatever words they put it.

Turn a goal into a short plan the user approves: the choices that are theirs, the steps
with exact commands, what each step produces and where it stops. This skill writes the
plan; it runs nothing but read-only commands. The other SensoryForge skills do the work.

**Steps.** Read the working style; Understand the goal; Find out what exists; Mark who decides; Size it; Write the plan; Hand over.

**Also covers.** When a component is missing.

### Worked example

The user says: "I want to see whether a sensor array can tell dots from edges." The
read-only checks the skill runs:

```bash
sensoryforge list-presets
# prints: tactile_sa1_ra1_adex
sensoryforge describe --section world
# prints: world shapes
sensoryforge describe --section evaluation
# prints: metric_packs
```

The plan it writes (shown to the user, not run):

```markdown
Goal: tell dots from edges with one sensor array.

| Choice | Value | Origin |
|---|---|---|
| Stimulus classes | dots, edges | you |
| Sensor | a shipped recipe, to be named | open: which one? |
| Sizes and ranges of each class | not set | open: yours to give |
| Data set size | not set | open: yours to give; time measured on one entry first |

Steps
1. sensoryforge-design-world: write and preview the world. Stops for your OK.
2. sensoryforge-build-dataset: splits and seeds. Stops for your OK.
3. sensoryforge-run-simulation: time one entry, then the rest.
4. sensoryforge-evaluate: report, read back with the raw numbers.
```

## Design a world

`sensoryforge-design-world`

**When an agent uses it.** Turn a plain-language description of a set of stimuli into a validated SensoryForge world file, and show a preview of what it draws. Use when someone describes the stimuli they want to generate or study (shapes, motions, vibrations, textures, kinds of input and how each varies), wants to change an existing world, or wants a world file checked or validated, in whatever words they put it.

A world is a declared population of stimuli: classes of stimulus whose fields are drawn
from ranges (axes). Today the declaration is a world file (YAML); the steps below are the
same for any declaration kind that `sensoryforge describe` lists. You end with a file that
validates, sample draws the user has looked at and a preview picture they have approved.

**Steps.** Read the working style; Find out what they mean; Map their words to the world's kinds; Ranges: never invent them; Write the file; Validate; Sample, then preview; Change it in words; Stop and report.

**Also covers.** Verify.

### Worked example

The user wants dots and edges of different sizes, one touch each. A first world:

```yaml
# file: world.yml
world:
  name: demo
  defaults:
    delay_ms:   {range: [0, 10]}
    touch_ms:   {range: [5, 15]}
    hold_ms:    {range: [20, 40]}
    release_ms: {range: [5, 15]}
    amplitude:  {range: [0.5, 1.0]}
    x_mm: {range: [-0.3, 0.3]}
    y_mm: {range: [-0.3, 0.3]}
  classes:
    dots:
      weight: 0.6
      layer: {shape: {kind: gaussian}}
      axes: {sigma_mm: {range: [0.15, 0.45]}}
    edges:
      weight: 0.4
      layer: {shape: {kind: bar, profile: gaussian, length_mm: 0}}
      axes:
        width_mm: {range: [0.05, 0.15]}
        orientation_deg: {range: [0, 180], circular: true}
```

```bash
sensoryforge world validate world.yml
# prints: class dots
sensoryforge validate --json --kind world world.yml
# prints: "valid": true
sensoryforge world sample world.yml -n 2 --seed 7
# prints: "class": "dots"
```

A range that the shape refuses is reported with its path, and the command exits 1:

```yaml
      layer: {shape: {kind: gaussian}}
```

The preview script:

```python
# file: preview.py
"""A contact sheet of a world: one row per draw, six times across the columns."""
import sys

import matplotlib

matplotlib.use("Agg")
import matplotlib.pyplot as plt

from sensoryforge.world import Canvas, load_world, render_movie, sample

# The canvas is the sensor's: grid rows, columns and spacing in the world's space unit.
ROWS, COLS, SPACING = 40, 40, 0.15
world_file, out = sys.argv[1], sys.argv[2]
duration_ms, n = float(sys.argv[3]), int(sys.argv[4])

canvas = Canvas.from_grid(ROWS, COLS, SPACING)
draws = sample(load_world(world_file), n=n, seed=0)
movies = [render_movie(d, canvas, dt_ms=1.0, duration_ms=duration_ms) for d in draws]
top = max(float(m.max()) for m in movies) or 1.0  # one colour scale for every panel
times = [round(k * (int(duration_ms) - 1) / 5) for k in range(6)]

fig, axes = plt.subplots(n, 6, figsize=(12, 2 * n), squeeze=False)
for r, (draw, movie) in enumerate(zip(draws, movies)):
    for c, t in enumerate(times):
        ax = axes[r][c]
        ax.imshow(movie[t].T, origin="lower", vmin=0.0, vmax=top)
        ax.set_xticks([])
        ax.set_yticks([])
        if r == 0:
            ax.set_title(f"t = {t} ms")
        if c == 0:
            ax.set_ylabel(draw.class_name)
fig.savefig(out, dpi=80)
print(f"{n} draws, written to {out}")
```

```bash
python preview.py world.yml preview.png 80 4
# prints: written to preview.png
```

## Ground assumptions

`sensoryforge-ground-assumptions`

**When an agent uses it.** Settle a model, parameter, range or unit that nobody has given, by asking the user or by finding sources they approve, and keep every assumption listed with where it came from. Use before writing any number into a plan, world or data-set file that arrives with no unit or far outside the range the skill or the world states, even for a plain edit; and when a value, an equation, a unit or "what is typical" is missing, when a plan or a file holds a value marked as an assumption, when someone asks for a source, a reference or "the right number", or before any value would be filled in from memory, in whatever words they put it.

Physics, models, parameters, ranges and units are not yours to supply, however plausible
a number looks and however sure you are. This skill is how a missing one gets an origin:
the user describes it, or you find sources, link them and write a short report for the
user to approve. Every value that ends up in a file is listed with where it came from.

**Steps.** Read the working style; Say exactly what is missing; Offer the two ways and let the user choose; When they describe it; When you look for sources; Record every assumption; Report back.

**Also covers.** Verify.

### Worked example

A world with one size range nobody has approved yet, and the table that records it:

```yaml
# file: world.yml
world:
  name: round
  defaults:
    hold_ms: {range: [20, 40]}  # you
  classes:
    dots:
      weight: 1.0
      layer: {shape: {kind: gaussian}}
      axes: {sigma_mm: {range: [0.15, 0.45]}}  # assumption: needs your OK
```

```markdown
# file: assumptions.md
| Value | Unit | Used in | Origin | Status |
|---|---|---|---|---|
| sigma_mm range 0.15 to 0.45 | mm | world.yml, classes.dots.axes | assumption: needs your OK | open |
```

After the user says "use 0.2 to 0.5, that is what I measured":

```yaml
# file: world_approved.yml
world:
  name: round
  defaults:
    hold_ms: {range: [20, 40]}  # you
  classes:
    dots:
      weight: 1.0
      layer: {shape: {kind: gaussian}}
      axes: {sigma_mm: {range: [0.2, 0.5]}}  # you
```

```markdown
# file: assumptions_approved.md
| Value | Unit | Used in | Origin | Status |
|---|---|---|---|---|
| sigma_mm range 0.2 to 0.5 | mm | world_approved.yml, classes.dots.axes | you (chat, 2026-10-27) | approved |
```

```python
# file: assumptions.py
"""Open assumptions in a file, and the rows of a table that have no origin."""
import sys

MARK = "assumption: needs your OK"
ORIGINS = ("you", "source:", "reasoning:", MARK)

path = sys.argv[1]
marked = [(n, ln.strip()) for n, ln in enumerate(open(path), 1) if MARK in ln]
for n, ln in marked:
    print(f"{path}:{n}: {ln}")
rows = opened = unsourced = 0
table = sys.argv[2] if len(sys.argv) > 2 else None
for n, ln in enumerate(open(table), 1) if table else []:
    cells = [c.strip() for c in ln.strip().strip("|").split("|")]
    if len(cells) < 5 or cells[0] == "Value" or set(cells[0]) <= set("-: "):
        continue
    rows += 1
    opened += cells[4] == "open"
    if not cells[3].startswith(ORIGINS):
        unsourced += 1
        print(f"{table}:{n}: no origin for {cells[0]!r}")
print(f"{len(marked)} marked in {path}; {rows} recorded ({opened} open); "
      f"{unsourced} without an origin")
sys.exit(1 if marked or opened or unsourced else 0)
```

```bash
sensoryforge validate --json --kind world world.yml
# prints: "valid": true
python assumptions.py world.yml assumptions.md
# prints: 1 marked in world.yml
# exit: 1
python assumptions.py world_approved.yml assumptions_approved.md
# prints: 0 marked in world_approved.yml
```

## Build a data set

`sensoryforge-build-dataset`

**When an agent uses it.** Turn a SensoryForge world into a data set, choosing the splits, the seed and the sizes with the user, and build its manifest without simulating anything. Use when someone wants training, validation or test examples, held-out classes, probes, long sessions or named draws from a world, or wants to change or rebuild a data set, in whatever words they put it.

A data set fixes a world, a seed, a duration and how many of what to draw in each split.
Building it writes a manifest, one row per entry, and simulates nothing, so it is cheap
and safe to repeat. You end with a data-set file, a built manifest and a short report.

**Steps.** Read the working style; Check the inputs; Choose the splits; Seed and duration; Write, validate, build; Count and report.

**Also covers.** Verify.

### Worked example

A world with two classes, a small data set from it, and the counts:

```yaml
# file: world.yml
world:
  name: demo
  defaults:
    delay_ms:   {range: [0, 10]}
    touch_ms:   {range: [5, 15]}
    hold_ms:    {range: [20, 40]}
    release_ms: {range: [5, 15]}
    amplitude:  {range: [0.5, 1.0]}
    x_mm: {range: [-0.3, 0.3]}
    y_mm: {range: [-0.3, 0.3]}
  classes:
    dots:
      weight: 0.6
      layer: {shape: {kind: gaussian}}
      axes: {sigma_mm: {range: [0.15, 0.45]}}
    edges:
      weight: 0.4
      layer: {shape: {kind: bar, profile: gaussian, length_mm: 0}}
      axes:
        width_mm: {range: [0.05, 0.15]}
        orientation_deg: {range: [0, 180], circular: true}
```

```yaml
# file: dataset.yml
dataset:
  name: demo
  world: world.yml
  seed: 7
  duration_ms: 80
  splits:
    train: {n: 4}
    test: {stratified: {bins: 2, per_bin: 1}}
```

```python
# file: count.py
"""Entries per split and class in a built data set, and how many are cut off."""
import collections
import json
import sys

rows = [json.loads(line) for line in open(sys.argv[1] + "/manifest.jsonl")]
counts = collections.Counter((r["split"], r["class"]) for r in rows)
for (split, cls), n in sorted(counts.items()):
    print(f"{split:8s} {cls:8s} {n}")
print(f"{len(rows)} entries, {sum(1 for r in rows if r['truncated'])} truncated")
```

```bash
sensoryforge validate --json --kind dataset dataset.yml
# prints: "valid": true
sensoryforge dataset build dataset.yml --out runs/demo
# prints: 8 entries
python count.py runs/demo
# prints: 8 entries, 0 truncated
```

## Run a simulation

`sensoryforge-run-simulation`

**When an agent uses it.** Simulate a SensoryForge data set (or one config) through a sensor and write one data bundle per entry, timed, resumable and splittable over jobs. Use when someone wants to run, simulate, encode or batch a data set or a stimulus through a recipe, design or config, to resume an interrupted run, or to spread a run over several jobs, in whatever words they put it.

A run simulates every entry of a data set through a sensor (receptive fields, filters,
neurons) and writes one data bundle per entry. It can take hours and gigabytes, so you
measure one entry first, say what the whole run costs and ask before starting it.

**Steps.** Read the working style; Check the inputs; Time one entry, then say what the run costs; Run; Scale; When entries fail; Verify and report.

### Worked example

A tiny data set on a shipped recipe: build it into the run's folder, check the plan, time
one entry, run the rest, and count.

```yaml
    amplitude:  {range: [0.5, 1.0]}

    dots:
```

## Evaluate

`sensoryforge-evaluate`

**When an agent uses it.** Evaluate a SensoryForge world or data set (audit the generated data, set it against what the world declared, run the checks) and read the report back in words, raw numbers first. Use when someone wants to check, audit, evaluate, validate or compare what a data set or a simulation produced, to look at the draws in the browser, or to share a snapshot, in whatever words they put it.

One command takes a world or a data set to a report folder: it builds the data set,
simulates it, audits the generated data (it never sees the world file), extracts what the
world declares for each entry, compares the two and runs reference-free checks. Your job
is to run it, then say what the report says: the numbers first, then what they mean, and
nothing the numbers do not support.

**Steps.** Read the working style; Check the inputs; Run it; Read the report back; Look and share; Stop and report.

### Worked example

A tiny world through a shipped recipe, and a summary of the report.

```yaml
# file: world.yml
world:
  name: demo
  defaults:
    delay_ms:   {range: [0, 10]}
    touch_ms:   {range: [5, 15]}
    hold_ms:    {range: [20, 40]}
    release_ms: {range: [5, 15]}
    amplitude:  {range: [0.5, 1.0]}
    x_mm: {range: [-0.3, 0.3]}
    y_mm: {range: [-0.3, 0.3]}
  classes:
    dots:
      weight: 1.0
      layer: {shape: {kind: gaussian}}
      axes: {sigma_mm: {range: [0.15, 0.45]}}
```

```python
# file: summarize.py
"""Say what an evaluation report folder says: status, counts, notes, failed checks."""
import json
import sys

folder = sys.argv[1] + "/evaluate"
pipe = json.load(open(folder + "/pipeline.json"))
print("status:", pipe["status"], "| error:", pipe["error"])
print("counts:", json.dumps(pipe["counts"]))
for note in pipe["notes"]:
    print("note:", note)
for check in json.load(open(folder + "/checks.json"))["checks"]:
    if check["status"] != "pass":
        print(check["status"], check["id"], "-", check["title"], "|", check["note"])
        print("  tests:", check["what"])
        print("  tested", check["tested"], "failed", check["failed"], check["numbers"])
compare = json.load(open(folder + "/compare.json"))
print("pairing:", json.dumps(compare["counts"]), "| difference is", compare["difference"])
```

```bash
python summarize.py runs/demo
# prints: status: ok
python -m sensoryforge.evaluate.compare runs/demo/evaluate runs/demo/evaluate
# prints: core.frames.duration
```

## Diagnose

`sensoryforge-diagnose`

**When an agent uses it.** Trace a surprising or bad SensoryForge result back to the draws, parameters and code behind it. Use when a report, check, plot or run gives something unexpected (a failed or skipped check, a silent or saturated population, a measured value far from the declared one, an entry that did not run, two runs that disagree), in whatever words they put it.

A bad number is a symptom. Your job is to find which entries it comes from, open their
draws, and say which of four places holds the cause, with the evidence for it and what is
not yet shown. You change nothing until the user has chosen what to change.

**Steps.** Read the working style; Pin down the symptom; Find the entries behind it; Open one entry; Sort the cause into one of four places; Test the cause, one change at a time; Stop and report.

### Worked example

A world whose draws start 30 to 60 ms in, in a data set cut to 40 ms. The report is built,
then traced; the user then chooses 130 ms, the longest a draw can take (60 + 15 + 40 + 15,
from the world's ranges), and the same check passes.

```yaml
# file: world.yml
world:
  name: late
  defaults:
    delay_ms:   {range: [30, 60]}
    touch_ms:   {range: [5, 15]}
    hold_ms:    {range: [20, 40]}
    release_ms: {range: [5, 15]}
    amplitude:  {range: [0.5, 1.0]}
    x_mm: {range: [-0.3, 0.3]}
    y_mm: {range: [-0.3, 0.3]}
  classes:
    dots:
      weight: 1.0
      layer: {shape: {kind: gaussian}}
      axes: {sigma_mm: {range: [0.15, 0.45]}}
```

```yaml
# file: dataset.yml
dataset:
  name: late
  world: world.yml
  seed: 7
  duration_ms: 40
  splits:
    train: {n: 6}
```


```python
# file: diagnose.py
"""Trace a surprising number in an evaluation report back to the draws behind it.

    python diagnose.py DIR odd             entries that did not run, are silent or unpaired
    python diagnose.py DIR largest ID [N]  the N entries where metric ID differs most
    python diagnose.py DIR entry ENTRY     what the data set holds about one entry

DIR is the folder given to `sensoryforge evaluate run --out`. It reads the world's
declaration (the manifest) on purpose: the audit stays blind, a diagnosis does not.
"""
import json
import sys
from pathlib import Path

from sensoryforge.world import read_batch_index

root, mode, rest = Path(sys.argv[1]), sys.argv[2], sys.argv[3:]


def rows(name):
    path = root / name
    return [json.loads(line) for line in open(path)] if path.exists() else None


def need(name):
    found = rows(name)
    if found is None:
        sys.exit(f"{root / name} is missing: run `sensoryforge evaluate run ... --out {root}`")
    return found


def short(value):
    return round(value, 4) if isinstance(value, float) else value


index = {r["entry"]: r for r in read_batch_index(root)}

if mode == "entry":
    entry = rest[0]
    manifest = rows("manifest.jsonl")
    if manifest is None:
        sys.exit(f"{root / 'manifest.jsonl'} is missing: build the data set into this folder "
                 f"(`sensoryforge dataset build DATASET --out {root}`)")
    row = next((r for r in manifest if r["entry"] == entry), None)
    if row is None:
        sys.exit(f"{entry} is not in the manifest; it starts {manifest[0]['entry']}, ...")
    print("entry", entry, "| class", row["class"], "| split", row["split"])
    print("duration_ms", row["duration_ms"], "| cut off by it:", row["truncated"],
          "| seeds", row["seeds"])
    print("draw values:", json.dumps({k: short(v) for k, v in row["draw"]["values"].items()}))
    print("timeline:", [(n, short(a), short(b)) for n, a, b in row["draw"]["timeline"]])
    done = index.get(entry)
    print("batch:", f"{done['status']} {done['error'] or ''}" if done else "not simulated here")
    compared = rows("evaluate/compare_entries.jsonl")
    if compared is None:
        print("no comparison: there is no evaluate/ report in this folder")
    for r in compared or []:
        if r["entry"] == entry:
            for p in r["pairs"]:
                print(" ", p["id"], "measured", short(p["measured"]), "declared",
                      short(p["declared"]), "diff", short(p["diff"]), p["pairing"])
    sys.exit(0)

pairs = {r["entry"]: r["pairs"] for r in need("evaluate/compare_entries.jsonl")}

if mode == "odd":
    found = 0
    for entry, row in index.items():
        if row["status"] != "ok":
            print(entry, "did not run:", row["status"], row["error"])
            found += 1
    for row in need("evaluate/audit_entries.jsonl"):
        bouts = [v["value"] for v in row["values"] if v["id"] == "core.frames.bouts"]
        if bouts and not any(bouts):
            print(row["entry"], "silent: no active stimulus frame")
            found += 1
    for entry, entry_pairs in pairs.items():
        for kind in sorted({p["pairing"] for p in entry_pairs} - {"ok", "unit_unchecked"}):
            ids = [p["id"] for p in entry_pairs if p["pairing"] == kind]
            print(entry, kind, "->", ", ".join(ids))
            found += 1
    sys.exit(1 if found else 0)
elif mode == "largest":
    metric, count = rest[0], int(rest[1]) if len(rest) > 1 else 5
    found = [
        (entry, p)
        for entry, entry_pairs in pairs.items()
        for p in entry_pairs
        if p["id"] == metric and p["diff"] is not None
    ]
    for entry, p in sorted(found, key=lambda item: -abs(item[1]["diff"]))[:count]:
        print(entry, "measured", short(p["measured"]), "declared", short(p["declared"]),
              "diff", short(p["diff"]), "resolution", p["resolution"])
else:
    sys.exit("modes: odd | largest ID [N] | entry ENTRY")
```

## Interpret a report

`sensoryforge-interpret-report`

**When an agent uses it.** Explain in plain words what a SensoryForge report's metrics, checks and comparison columns mean and what is typical for the data in front of you. Use when someone asks what a number, metric, check, column or file in a report means, whether a value is normal or typical, or how to read a report, in whatever words they put it.

A report is numbers with definitions. Your job is to say what a number measures, in what
unit and at what resolution, and what is typical for this data set, from the report and
the contract only. You never judge a value good or bad: the report states no tolerance.

**Steps.** Read the working style; Find what is being asked about; Say what it measures; Say what is typical, and only from these sources; Read a comparison, a check, a file; Stop and offer the next step.

### Worked example

A small report, then one metric explained from it: its row and this data set's spread.

```yaml

    release_ms: {range: [5, 15]}
    amplitude:  {range: [0.5, 1.0]}
    x_mm: {range: [-0.3, 0.3]}
```

```python
# file: explain.py
"""What a report holds about a metric: its row and this data set's own spread.

    python explain.py REPORT --list     every metric id in the report
    python explain.py REPORT ID         its unit, resolution and scope, then the spread

REPORT is the folder given to `sensoryforge evaluate run --out`. The meaning of a metric is
in the report contract, not here.
"""
import json
import sys

folder, what = sys.argv[1] + "/evaluate", sys.argv[2]
audit = json.load(open(folder + "/audit.json"))
metrics = {m["id"]: m for m in audit["metrics"]}

if what == "--list":
    for metric_id, m in metrics.items():
        print(metric_id, "|", (m["unit"] or {}).get("symbol"), "|", m["scope"])
    sys.exit()

m = metrics[what]
unit = m["unit"] or {}
print(what, "| unit:", unit.get("symbol"), "| origin:", unit.get("origin"))
print("resolution", m["resolution"], "| scope", m["scope"], "| level", m["level"])
groups = {"data set": audit["dataset"]}
for kind, labels in audit["groupings"].items():
    groups.update({kind + " " + label: group for label, group in labels.items()})
columns = ("n", "n_null", "min", "q05", "q50", "q95", "max", "mean", "std")
for name, group in groups.items():
    for row in group["summaries"]:
        if row["id"] == what:
            where = row.get("population") or row.get("channel") or ""
            numbers = [f"{c} {row[c]:.4g}" if row[c] is not None else f"{c} -" for c in columns]
            print(name, where, "|", ", ".join(numbers))
```

## Workflow

`sensoryforge-workflow`

**When an agent uses it.** Carry a SensoryForge job from a goal to an explained report by chaining the other skills, step by step or end to end as the user chooses. Use when someone wants the whole job or several steps in a row, says "take it from here", "do all of it" or "what next", or starts SensoryForge work without naming a step, in whatever words they put it.

A SensoryForge job usually runs plan, world, data set, simulation, evaluation, then an
explanation. This skill runs that chain with the skill each step names, at the pace the
user chooses, and keeps them informed of where the job stands. It does none of the steps
itself: each step's skill does it, with its own checks and stops.

**Steps.** Read the working style; Find where the job stands; Settle the plan and the pace; Run the chain; Two kinds of stops; Finish.

**Also covers.** Hooks.

### Worked example

A small job from the first step the folder is missing, checking where it stands after
each step. The plan it would write is shown, not run.

```markdown
Goal: see how a sensor answers small round stimuli.

Pace: I will ask before each next step (your saved style); say "carry on" to change it.

Steps
1. design-world: the file below. Stops for your OK.
2. build-dataset: 4 entries (you), seed 7 (you). Stops for your OK.
3. run-simulation: one entry timed, then the rest.
4. evaluate: the report, read back with the raw numbers.
```

```python
# file: where.py
"""Where a SensoryForge job stands: which of the chain's outputs a folder holds."""
import json
import sys
from pathlib import Path

from sensoryforge.world import read_batch_index

folder = Path(sys.argv[1])
manifest = folder / "manifest.jsonl"
entries = sum(1 for _ in open(manifest)) if manifest.exists() else 0
rows = read_batch_index(folder) if (folder / "index").exists() else []
done = sum(1 for row in rows if row["status"] == "ok")
print("data set built:", f"{entries} entries" if entries else
      "not in this folder" if done else "not yet")
print("simulated:", ("not yet" if not done else f"{done} of {entries}" if entries
                     else f"{done} ok (no manifest here to count against)"))
pipeline = folder / "evaluate" / "pipeline.json"
if pipeline.exists():
    report = json.load(open(pipeline))
    print("evaluated:", report["status"], json.dumps(report["counts"]))
else:
    print("evaluated: not yet")
```
